\section{Resumen ejecutivo}
\begin{resumenbox}[Finalidad del proyecto]
El proyecto busca desarrollar tres estandartes móviles e independientes para representar a la Escuela Profesional de Ingeniería Mecánica Eléctrica durante la parada universitaria. El módulo izquierdo llevará la palabra \textbf{MECÁNICA}; el módulo central, de mayor ancho, incluirá el nombre institucional y un símbolo de Zeus; el módulo derecho llevará la palabra \textbf{ELÉCTRICA}. La iluminación se realizará con LED direccionables WS2812, controladores ESP32, efectos dinámicos, sincronización inalámbrica y una interfaz de control desde teléfono móvil.
\end{resumenbox}

El trabajo se organiza en dos niveles. El primero es una \textbf{simulación integrada}, en la que un ESP32 virtual controla tres zonas LED, una pantalla OLED, botones y entradas analógicas. El segundo es la \textbf{arquitectura física final}, donde cada estandarte tendrá su propio ESP32 y batería, mientras el módulo central actuará como coordinador mediante ESP-NOW y alojará una página web local mediante Wi-Fi.

\begin{successbox}[Entregables incluidos en este paquete]
\begin{itemize}
  \item Documento editable en \LaTeX{} y PDF compilado.
  \item Simulador visual interactivo en HTML con vistas de estandarte, circuito y red inalámbrica.
  \item Proyecto integrado listo para importar en Wokwi.
  \item Proyecto local para Visual Studio Code + PlatformIO + Wokwi.
  \item Código base para tres ESP32: central, Mecánica y Eléctrica.
  \item Diagramas, enlaces, códigos QR, pinout, cronograma, pruebas, riesgos y presupuesto preliminar.
\end{itemize}
\end{successbox}

\begin{alertbox}[Alcance real de Wokwi]
Wokwi permite simular el ESP32, GPIO, ADC, I2C, Wi-Fi y dispositivos WS2812. Sin embargo, no admite varios microcontroladores conectados dentro de un único proyecto. Por ello, la simulación inicial integra las tres zonas en un solo ESP32, mientras la comunicación ESP-NOW debe verificarse posteriormente con tres placas físicas o con varias instancias separadas del simulador. \cite{wokwi-faq,wokwi-esp32}
\end{alertbox}

\section{Antecedentes y necesidad}
El repositorio original propone un estandarte reactivo al sonido mediante ESP32, micrófono MAX4466, tiras WS2812 y scripts de análisis de audio. Para la parada universitaria se requiere ampliar el alcance y adaptar la propuesta a tres estructuras móviles que no estarán unidas por cables. Esto obliga a incorporar:
\begin{itemize}
  \item controladores y baterías independientes;
  \item sincronización inalámbrica;
  \item control desde celular sin depender de internet;
  \item protección eléctrica y limitación de corriente;
  \item diseño mecánico ligero, desmontable y resistente a vibraciones;
  \item simulación previa del firmware, conexiones y efectos visuales.
\end{itemize}

\section{Objetivos}
\subsection{Objetivo general}
Diseñar, simular y validar un sistema modular de iluminación dinámica para tres estandartes móviles de Ingeniería Mecánica Eléctrica, con control inalámbrico, operación autónoma, protección eléctrica y capacidad de interacción desde un teléfono móvil.

\subsection{Objetivos específicos}
\begin{enumerate}
  \item Representar gráficamente el ESP32, drivers, entradas, tiras LED, matriz central y cableado en Wokwi.
  \item Programar efectos diferenciados para Mecánica, Zeus y Eléctrica.
  \item Crear una simulación visual local que permita explicar el funcionamiento sin depender del hardware.
  \item Diseñar la red de tres ESP32 mediante ESP-NOW y el control web local mediante Wi-Fi.
  \item Definir el tendido de potencia, señales, protecciones y conectores por módulo.
  \item Establecer cálculos preliminares de consumo y autonomía.
  \item Organizar las actividades en un cronograma con responsables, entregables y criterios de aceptación.
  \item Preparar una lista de materiales y una matriz de pruebas antes de construir el prototipo.
\end{enumerate}

\section{Instalación paso a paso del entorno de simulación}
\subsection{Ruta rápida: Wokwi en navegador}
\begin{enumerate}
  \item Abrir \url{https://wokwi.com/projects/new/esp32}.
  \item Crear o iniciar sesión para guardar el proyecto y obtener un enlace compartible.
  \item Reemplazar el contenido de \texttt{sketch.ino} con el archivo incluido en \texttt{wokwi\_integrado}.
  \item Abrir \texttt{diagram.json} y reemplazarlo con el diagrama incluido.
  \item Crear \texttt{libraries.txt} con las bibliotecas indicadas.
  \item Presionar \textit{Start Simulation}.
  \item Mover los potenciómetros de sonido y brillo.
  \item Pulsar MODO, COLOR y SECUENCIA o utilizar las teclas M, C y S.
  \item Revisar la OLED y el monitor serial.
  \item Guardar el proyecto para que Wokwi genere su enlace público.
\end{enumerate}

\subsection{Ruta profesional: VS Code + PlatformIO + Wokwi}
\begin{enumerate}
  \item Instalar Visual Studio Code.
  \item Buscar e instalar la extensión oficial \textit{PlatformIO IDE}.
  \item Instalar la extensión \textit{Wokwi Simulator}.
  \item Abrir la carpeta \texttt{platformio\_simulacion}.
  \item Ejecutar \textit{PlatformIO: Build}.
  \item Verificar que se generen \texttt{firmware.bin} y \texttt{firmware.elf}.
  \item Ejecutar \textit{Wokwi: Start Simulator}.
  \item Para un servidor web futuro, activar el reenvío de puerto en \texttt{wokwi.toml}. \cite{wokwi-config}
\end{enumerate}

\begin{lstlisting}[style=code,language={},caption={Configuración incluida en wokwi.toml}]
[wokwi]
version = 1
firmware = '.pio/build/esp32dev/firmware.bin'
elf = '.pio/build/esp32dev/firmware.elf'

# Etapa posterior: servidor web virtual
# [[net.forward]]
# from = 'localhost:8180'
# to = 'target:80'
\end{lstlisting}

\subsection{Reglas de tendido físico}
\begin{itemize}
  \item No hacer circular la corriente de las tiras a través del pin 5 V del ESP32.
  \item Mantener la línea de datos corta entre el driver y el primer LED.
  \item Colocar la resistencia de 330--470 \si{\ohm} cerca de la salida del driver.
  \item Colocar un condensador de 470--1000 \si{\micro\farad} cerca del inicio de cada tira.
  \item Realizar inyección de 5 V y GND en varios puntos cuando la tira sea larga.
  \item Separar físicamente cables de potencia y señales cuando sea posible.
  \item Incorporar alivio de tensión y conectores con seguro para resistir vibraciones.
\end{itemize}

\subsection{Razón para utilizar ESP-NOW}
ESP-NOW permite comunicación directa entre dispositivos ESP32 sin router, con baja sobrecarga y envío de comandos pequeños. El maestro no debe transmitir el estado individual de cada LED; solamente enviará modo, brillo, color, velocidad, secuencia y hora de inicio. Cada receptor ejecutará localmente sus efectos. \cite{espnow}

\subsection{Ecuaciones de dimensionamiento}
\begin{align}
I_{\max} &= N_{LED}\,I_{LED,\max} \\
P_{\max} &= V_{LED}\,I_{\max} \\
E_{req} &= P_{prom}\,t \\
C_{Ah} &= \frac{E_{req}}{V_{bat}\,\eta}
\end{align}

Donde $\eta$ es la eficiencia total del convertidor y del cableado. Para el diseño final se deberá medir el consumo del efecto real y no depender únicamente del máximo teórico.

Caída de tensión & Medir inicio y final de tiras & Diferencia aceptable, sin cambios de color\\

Autonomía & Ejecutar programa real & Cumple duración más margen\\
Vibración & Simular marcha & Sin desconexiones\\
Visibilidad diurna & Probar al exterior & Texto y efectos identificables\\
Emergencia & Activar apagado & Corte inmediato y seguro\\
\bottomrule
\end{longtable}

\section{Manual operativo preliminar}
\subsection{Antes de la parada}
\begin{enumerate}
  \item Cargar las tres baterías y verificar tensión.
  \item Revisar fusibles, conectores y fijaciones.
  \item Encender cada módulo individualmente.
  \item Verificar el modo seguro de cada lateral.
  \item Encender el central y conectar el celular.
  \item Ejecutar una secuencia general.
  \item Confirmar autonomía y llevar repuestos.
\end{enumerate}

\subsection{Durante la parada}
\begin{itemize}
  \item Mantener brillo moderado durante el recorrido normal.
  \item Reservar el modo Tormenta para momentos breves.
  \item Evitar modificar el cableado con el sistema energizado.
  \item Designar una sola persona para el control desde celular.
  \item Tener acceso inmediato a los interruptores generales.
\end{itemize}

\subsection{Después de la actividad}
\begin{itemize}
  \item Apagar los módulos antes de desconectar baterías.
  \item Revisar temperatura, conectores y cables.
  \item Cargar baterías según el procedimiento del fabricante.
  \item Registrar fallas y mejoras para el siguiente uso.
\end{itemize}

% ============================================================
\section{Entregables y criterios de cierre}
El proyecto se considerará listo para la parada cuando cumpla lo siguiente:
\begin{enumerate}
  \item Simulación integrada aprobada por el equipo.
  \item Diseño visual y dimensiones cerradas.
  \item Tres ESP32 sincronizados mediante ESP-NOW.
  \item Control web accesible desde al menos dos teléfonos de prueba.
  \item Consumo medido y limitado por módulo.
  \item Autonomía comprobada con margen.
  \item Estructura resistente al movimiento.
  \item Modo seguro y apagado de emergencia verificados.
  \item Manual, repuestos y responsables definidos.
\end{enumerate}

\section{Conclusiones y decisión recomendada}
La ruta más segura y eficiente es comenzar con Wokwi y el simulador visual local, aprobar la apariencia y los modos, y recién después cerrar el número de LED y el sistema de baterías. La arquitectura final debe usar tres ESP32, ESP-NOW entre módulos y una página web local alojada en el ESP32 central.

\begin{successbox}[Siguiente acción inmediata]
Abrir \texttt{simulacion\_visual/Simulador\_Visual\_Estandarte\_IME.html}, revisar la secuencia Mecánica--Zeus--Eléctrica y luego importar la carpeta \texttt{wokwi\_integrado} en Wokwi. Después de aprobar los efectos, se debe definir la cantidad real de LED y construir un prototipo de 20--30 LED.
\end{successbox}
